# Lumen frontend

Next.js 16 app for the Lumen editor — landing page, auth, dashboard, and the LaTeX editor
workspace built on Monaco.

See the [root README](../README.md) for the whole system; this covers the frontend alone.

> **This is Next.js 16.** APIs, conventions and file structure differ from older versions.
> Read the relevant guide in `node_modules/next/dist/docs/` before writing code, and heed
> deprecation notices. `AGENTS.md` carries the same warning and is generated by Next —
> don't hand-edit it.

## Running

**Use bun, not npm.** `bun.lock` is the only lockfile, the Dockerfile builds on
`oven/bun`, and `packageManager` pins it. Running `npm install` creates a competing
`package-lock.json`.

```bash
bun install
bun dev          # :3000
bun run build
bun run lint
```

The app needs the API. From the repo root, `docker compose up -d` starts Postgres and the
backend on `:9000`, which is what `BACKEND_URL` defaults to.

## Layout

```
app/
  (marketing)/        public landing page
  (dashboard)/        dashboard, projects, templates — shares a layout
  project/[id]/       the editor workspace
  login/ signup/
  api/                route handlers that proxy the backend and own the cookies
components/
  ui/                 shadcn primitives — generated, leave them alone
  editor-sidebar/     file tree: header, tabs, tree nodes, utils
lib/
  auth/               backend client, cookies, JWT helpers, route auth
  http/client.ts      the browser-side API client
  stores/             Zustand stores shared across routes
  projects.ts         turns the API's flat file list into a tree
proxy.ts              route protection and silent token refresh
```

### Where a component goes

- Shared across routes → `components/`
- Used by one route → `app/<route>/components/`
- Page state → `app/<route>/use-<route>-hook.ts`

Filenames are lowercase kebab-case, no exceptions. When a component grows past roughly 200
lines, convert it to a folder, split by responsibility, and keep the main export named
after the folder with an `index.ts` re-export — so the import path never changes.
`components/editor-sidebar/` and `app/project/[id]/components/editor-workspace/` are the
worked examples.

### Styling

Colours come **only** from the semantic tokens in `app/globals.css` — `bg-background`,
`text-foreground`, `text-muted-foreground`, `bg-primary/10`, `border-border`. Never raw
Tailwind palette classes (`bg-zinc-100`, `text-blue-500`) and never hex literals. The
editorial palette on the marketing and auth pages (`text-editorial-ink`,
`bg-editorial-paper`) is part of the same token set.

## Data flow

The browser never calls the API directly. `lib/http/client.ts` uses **relative** paths to
Next route handlers under `app/api/`, which forward to FastAPI with
`lib/auth/backend.ts` and set httpOnly session cookies. Port 9000 is never reachable from
the browser.

`proxy.ts` protects `/dashboard`, `/projects`, `/templates` and `/project/*`: it bounces
anonymous visitors to `/login`, sends signed-in users away from `/login` and `/signup`,
and silently refreshes an expired access token before the page renders.

`requestApi` normalises every response to `{ success, message, data }`. **`message` is
`null` when the response carried none**, which is what lets each caller supply its own
wording:

```ts
const { status, payload } = await postApi("/api/auth/login", { email, password });
if (status < 200 || status >= 300 || !payload.success) {
  setError(payload.message ?? "Unable to log in right now.");
}
```

## State

Zustand, no middleware. One store per concern:

| Store | Owns |
|---|---|
| `app/project/[id]/use-project-editor-hook.ts` | the whole editor: files, tabs, buffers, panels, AI chat |
| `app/login/use-login-hook.ts`, `app/signup/use-signup-hook.ts` | form state and validation |
| `app/(dashboard)/use-dashboard-*.ts` | dashboard layout and project list |
| `lib/stores/theme-store.ts` | light/dark |

Select narrowly — `useStore((s) => s.value)` — and never build a new object inside a
selector. Stores are plain objects, so actions can be called outside React with
`useProjectEditorHook.getState().action()`; that is how they are tested.

The editor store coalesces Monaco's per-keystroke change events before sending them to the
snapshot API, so typing a word is one request payload rather than five.

## Tests

```bash
bun run test            # unit, then e2e
bun run test:unit       # 121 tests, no browser
bun run test:e2e        # 24 Playwright tests (needs the backend)
bun run test:e2e:local  # the subset needing no backend
bun test auth           # one feature
```

A feature owns a folder of the same name in `tests/unit/` and `tests/e2e/`. E2E specs take
named screenshots as proof via the `proof` fixture, landing in
`tests/artifacts/screenshots/<feature>/<spec>/<test>/`.

Two rules worth knowing before writing any: mock **axios**, never our own modules
(`mock.module` is process-global in bun), and tag anything needing a live API `@backend`.
Full details in [`tests/README.md`](tests/README.md).

## Adding shadcn components

```bash
bunx --bun shadcn@latest add dialog
```

They land in `components/ui/`. Prefer composing existing primitives over new dependencies.
